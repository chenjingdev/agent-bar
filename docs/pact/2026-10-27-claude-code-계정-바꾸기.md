# Claude Code 계정 바꾸기
## 목적
`/login`의 브라우저 과정 없이, AgentBar에서 클릭 한 번으로 Claude Code의 로그인 계정을 바꾼다. 사용자 원문: "그냥 로그인만 편했으면 좋겠음. 내가 수동으로 클릭해도됨"
## 범위
- Claude Code의 기본 로그인 한 칸을 바꾼다. 기본 로그인은 폴더 변수(`CLAUDE_CONFIG_DIR`, `CLAUDE_SECURESTORAGE_CONFIG_DIR`) 없이 부른 Claude Code가 쓰는 로그인이다(Keychain "Claude Code-credentials"). 버튼은 AgentBar의 Claude 계정 창에 둔다. 집 Mac에서 만들고 확인한다. 회사 Mac은 설치한 뒤 사용자가 눌러 확인한다 [AI 가정].
## 하지 않는 것
- 세션마다 다른 계정, 자동 전환, 열린 세션 다시 시작. 사용량 로그인을 AgentBar 파일에 두는 지금 방식의 약관 검토는 따로 다룬다.
- 다음 판 후보: 직전 계정으로 되돌리기, 열린 세션 수 표시, 메뉴 막대에 계정 표시, 한도 90% 알림, Codex 계정 바꾸기
## 기능
- F1 Claude 계정 창 맨 위의 "Use in Claude Code" 버튼을 한 번 누르면 Claude Code가 그 계정으로 바뀐다. 지금 Claude Code가 쓰는 계정의 창에는 버튼 대신 "In Claude Code"가 보인다 [사용자]
  - 케이스: 그 계정의 빌려줄 로그인이 없거나 만료됨 → 이유를 보이고, 브라우저 로그인을 한 번 한 뒤 바뀐다(기다리는 동안 Cancel, 5분이 지나면 끝냄)
  - 케이스: 바꾸기 실패 → 계정 창에 이유를 한 줄로 보인다
- F2 한 번에 한 계정이다. 바꾸면 열린 세션까지 모든 Claude Code 세션이 새 계정을 쓴다 [사용자]
  - 케이스: 바꾼 뒤 → 결과 줄에 "Claude Code now uses …"와 "Open sessions switch within 30 s. Remote Control disconnects."를 보인다
- F3 다른 계정으로 바꾸면 그때까지 Claude Code에 있던 로그인을 AgentBar가 그 계정의 빌려줄 로그인으로 돌려받는다. 그래서 그 계정으로 돌아갈 때도 브라우저 로그인이 없다 [사용자: 범위 동의]
  - 케이스: AgentBar가 만들지 않은 로그인(처음 누를 때, 터미널 `/login` 뒤) → 그 계정이 AgentBar에 있으면 그대로 돌려받는다
  - 케이스: Claude Code에 있던 계정이 AgentBar에 없음 → 계정 창 안의 확인 줄(Cancel 포함)로 "이 로그인은 Claude Code에서 사라진다"고 먼저 묻는다
- F4 빌려줄 로그인은 사용량 로그인과 따로 계정마다 하나씩 둔다. 바꾸기에 문제가 생겨도 사용량 표시는 그대로다 — 로그인을 옮기면 토큰이 바뀌어서 한 로그인을 둘이 나눠 쓸 수 없다 [AI 가정]

## 공통 규칙
- R1 Claude Code에 로그인을 넣는 일은 Claude Code의 공식 명령(`claude auth login`에 refresh token을 넘기는 방식)으로만 한다. AgentBar는 Claude Code의 로그인 항목을 직접 쓰지 않는다 — 예전 세 번의 시도는 직접 쓰다가 낡은 사본과 Keychain 허용 창 때문에 실패했다 [AI 가정]
- R2 바꾸기 중에 Keychain 허용 창이 한 번도 뜨지 않는다. 사용자 원문: "키체인은 왜 계속 물어보는거야?" [사용자: 2026-09-20]
- R3 AI는 시험할 때 실제 Claude Code 로그인을 바꾸지 않는다. 따로 떼어 둔 폴더와 버릴 로그인으로 시험하고, 실제 바꾸기는 사용자가 직접 눌러 본다 — 실제 로그인을 바꾸면 지금 이 대화와 열린 세션의 계정도 바뀐다 [AI 가정]
<details><summary>그 밖의 AI 가정 11개</summary>

- R4 계정이 같은지는 계정 UUID와 조직 UUID 쌍으로 판단한다. 등록된 계정의 계정 UUID는 그 계정 로그인 폴더의 `.claude.json`(`oauthAccount`)에서 한 번 채우고, 조직 UUID가 등록된 값과 같을 때만 채운다. 빌려줄 로그인과 기본 로그인도 각자의 `.claude.json`에서 같은 쌍을 읽는다 — 지금 등록된 Claude 계정에는 계정 UUID가 없고, `claude auth status --json`도 내지 않는다 [AI 가정]
- R5 로그인을 넣고 빼는 일은 Claude Code의 공식 명령에 맡겨 그 명령이 자기 잠금을 잡게 한다. AgentBar는 자기 바꾸기 작업을 한 번에 하나만 한다. 앞 계정 토큰은 기본 칸이 새 계정으로 바뀐 뒤에 빼내 다시 빌려준다. 그 사이 열린 세션이 앞 토큰을 이미 돌렸으면 빼내기는 실패로 끝나고 F11이 받는다 — 한 토큰을 둘이 쓰면 로그인이 통째로 폐기될 수 있고(clauth #52), CLI의 사적 잠금 형식을 흉내 내면 판이 바뀔 때 깨진다 [AI 가정]
- R6 옮긴 뒤 남은 낡은 사본은 이 Mac에서만 지운다. 로그아웃은 쓰지 않는다. 지우기와 지운 뒤 확인은 계정 삭제 코드(`AccountFiles`)와 같은 방식으로 한다 — 서버 폐기가 옮겨 간 새 로그인까지 끊을 수 있다 [AI 가정]
- R7 빌려줄 로그인은 `~/.agentbar/multi-account-v1/lend/` 아래 계정 UUID 폴더(0700)에 Claude Code가 저장한다. 두 폴더 변수를 이 폴더로 준다. 사용량 로그인 폴더와 같이 쓰지 않고, 이 폴더에는 `.credentials.json`을 만들지 않는다 — AgentBar가 토큰을 따로 보관하지 않는다. 폴더가 같으면 Keychain 이름도 겹친다 [AI 가정]
- R8 Claude Code는 AgentBar의 최소 환경(`ProviderCLI.processEnvironment()`)으로 부르고, 필요한 변수만 더한다. 기본 로그인에 쓸 때는 폴더 변수를 주지 않는다 — 물려받은 변수가 엉뚱한 폴더나 계정에 쓰지 않게 한다 [AI 가정]
- R9 바꾼 뒤 Claude Code 로그인을 다시 읽어 계정이 맞는지 확인한다. 다르면 실패로 알린다 — 확인 없이 성공이라고 하지 않는다 [AI 가정]
- R10 Claude Code의 Keychain 항목은 `/usr/bin/security`로만 읽는다. AgentBar가 Security API로 직접 읽지 않는다 — Claude Code가 만든 항목은 이 프로그램을 믿는다 [AI 가정]
- R11 시험 코드는 대상 칸을 바깥에서 받는다. 시험할 때는 두 폴더 변수를 늘 시험 폴더로 준다 — 변수 없이 부르면 실제 기본 로그인에 쓴다 [AI 가정]
- R12 기존 규칙 "AgentBar never imports or follows the login used by Claude"(README 20, 41, 45, 73줄)는 사용량 읽기에 그대로 둔다. "Use in Claude Code"만 예외로 README에 적는다. 기본 로그인을 건드리지 않는지 보는 기존 시험도 그대로 둔다 [AI 가정]
- R13 토큰 값은 화면, 로그, 오류 메시지 어디에도 남기지 않는다 — 시크릿이다 [AI 가정]
- R14 새 문구는 앱처럼 영어로 쓴다(예: "Use in Claude Code", "In Claude Code") — 앱의 다른 문구가 모두 영어다 [AI 가정]

## 결정 기록
- Ruling: 앞 계정 토큰 빼내기를 CLI 내부 잠금(`.oauth_refresh.lock`) 재구현에서 공식 명령에 맡기는 방식으로 바꿨다(R5, F11) — CLI의 사적 잠금 형식은 Claude Code 판이 바뀌면 깨지고, 공식 명령이 이미 자기 잠금을 잡는다 — 틀리면 바꾸는 중 열린 세션의 토큰 갱신과 겹쳐 앞 계정 로그인이 폐기될 수 있다
- Ruling: F11의 "아무것도 바꾸지 않고 멈춘다"는 새 계정을 기본 칸에 넣는 단계의 실패에만 쓴다. 앞 계정 돌려받기가 네트워크 오류나 시간 초과로 실패하면 메모리의 토큰으로 두 번 더 해 보고, 그래도 안 되면 바꾸기는 그대로 두고 결과 줄에 그 계정은 다음에 브라우저 로그인이 필요하다고 더한다 — R5대로 기본 칸을 먼저 바꾸므로 돌려받을 때는 이미 바뀐 뒤다 — 틀리면 네트워크가 불안정할 때 앞 계정 로그인을 브라우저로 한 번 더 받아야 한다
- Ruling: 빌려줄 로그인 폴더 이름은 AgentBar 계정 id로 한다(R7의 "계정 UUID") — 같은 Claude 계정이 두 조직에 있으면 Claude 계정 UUID만으로는 폴더가 겹친다 — 틀리면 AgentBar에서 계정을 지우고 다시 만들 때 빌려줄 로그인을 다시 받아야 한다
- Ruling: 바꾸던 중 AgentBar가 꺼질 때(F5)를 위한 기록에는 토큰 없이 대상, 앞 계정, 단계만 남긴다. 기본 칸을 바꾼 뒤 꺼졌으면 다음 실행 때 남은 정리를 끝내고, 메모리에만 있던 앞 계정 토큰은 잃으므로 그 계정은 다음에 브라우저 로그인이 필요하다고 알린다 — R7에 따라 AgentBar는 토큰을 파일에 두지 않는다 — 틀리면 그 드문 경우 앞 계정 로그인을 브라우저로 한 번 더 받아야 한다
- Ruling: F5의 기록은 기본 칸에 처음 쓰기 직전에 남기고, F7 로그의 시작 줄은 맨 앞에 남긴다 — 그 전에는 기본 칸이 바뀐 것이 없어 되돌릴 것도 없다 — 틀리면 잃는 것은 없다
- Ruling: 처음 빌려주기로 브라우저 로그인을 거친 뒤에는 기본 칸을 다시 읽고, 이미 그 계정인지와 모르는 계정인지를 다시 판단한다 — 몇 분 사이 열린 세션이 토큰을 갱신했거나 사용자가 다른 로그인을 했을 수 있다 — 틀리면 security 읽기가 한 번 늘 뿐이다
- Ruling: F11의 무효는 Claude Code가 `invalid_grant`나 400·401을 낸 경우만이다. 403, 429, 5xx, 네트워크 오류, 모르는 문구는 일시로 본다. 시간 초과여도 그때까지 나온 출력에 거절이 있으면 무효다. 2.1.312의 실물 문구는 "Login failed: Request failed with status code 400"(무효)와 "Login failed: connect ECONNREFUSED …"(일시)다 — 명세가 무효로 정한 것이 이것뿐이다 — 틀리면 Claude Code가 무효를 다른 문구로 낼 때 "Try again"만 되풀이된다. 그때는 로그의 출력으로 판별 문구를 고친다
- Ruling: 비교할 근거(조직 UUID, 그리고 계정 UUID나 이메일)가 없는 계정은 아무것도 바꾸지 않고 거절한다 — F12와 R9를 할 수 없다 — 틀리면 그런 계정은 버튼이 막힌다
- Ruling: 기본 칸에 넣는 명령이 실패하거나 시간 초과여도 기본 칸의 신원과 refresh token을 다시 읽는다. 새 계정 로그인이 들어갔으면 성공으로 잇는다. 읽기 전과 같으면 아무것도 안 바뀐 것이다. 그 밖이면 브라우저로 넘어가지 않고 정리한 뒤 끝낸다 — 60초 시간 초과는 명령이 일을 마치고 늦게 끝난 경우를 배제하지 못하고, 믿을 수 없는 칸에 새 로그인을 넣으면 앞 로그인이 사라지거나 같은 토큰이 두 번 쓰인다 — 틀리면 그 드문 경우 사용자가 한 번 더 누른다
- Ruling: 명령이 성공(0)으로 끝나면 새 계정의 빌려줄 사본은 쓴 것으로 보고 지운다. 그 뒤 R9 확인이 실패하면 새 계정도 다음에 브라우저 로그인이 필요하다고 알린다 — 같은 토큰을 다시 넘기지 않는다 — 틀리면 명령이 아무것도 쓰지 않은 드문 경우 멀쩡한 사본을 지워 브라우저 로그인이 한 번 더 뜬다
- Ruling: 앞 계정 로그인은 그 refresh token이 기본 칸을 떠난 것을 확인했을 때만 돌려준다. 칸에 그대로 있거나 같은 계정이 다른 토큰으로 있으면(열린 세션이 갱신함) 돌려주지 않는다. 같은 계정·다른 토큰은 Keychain만 늦게 바뀐 경우와 겉이 같지만, 낡은 토큰을 쓰는 쪽이 더 위험하다 — R5, 한 토큰을 두 번 쓰면 로그인이 통째로 폐기될 수 있다 — 틀리면 드문 경우 앞 계정 로그인이 알림 없이 사라져 그 계정을 브라우저로 한 번 로그인한다
- Ruling: 명령은 성공(0)했는데 기본 칸을 못 읽으면 앞 토큰을 돌려주지 않는다. 그 계정 폴더에 로그인이 없으면 다음에 브라우저 로그인이 필요하다고 알린다 — 칸에 앞 토큰이 남았을 수 있어 쓰지 않지만, 성공했으면 새 계정이 들어갔을 가능성이 높다 — 틀리면 앞 계정이 칸에 그대로일 때 거짓 알림이 뜬다
- Ruling: 돌려주기 재시도는 3초, 6초 뒤 두 번이다. 다시 하기 전에 앞 계정 폴더를 보고, 첫 시도가 이미 저장했으면 거기서 끝낸다 — 늦게 끝난 첫 시도를 되풀이하면 같은 토큰을 두 번 쓴다 — 틀리면 기다리는 시간만 달라진다
- Ruling: 앞 계정 폴더에 그 계정 로그인이 이미 있으면 돌려주기가 실패해도(복구 포함) 다음에 브라우저 로그인이 필요하다고 알리지 않는다 — 거짓 알림을 피한다 — 틀리면 그 폴더 로그인이 이미 죽었을 때 다음에 쓸 때 걸러져 브라우저가 한 번 뜬다
- Ruling: 빌려줄 폴더에 다른 계정 로그인이나 refresh token 없는 로그인이 있으면 지우고 처음 빌려주기로 간다 — 엉뚱한 로그인을 기본 칸에 넣지 않는다 — 틀리면 브라우저 로그인이 한 번 더 뜬다
- Ruling: 쓴 사본의 Keychain 항목이 지워지지 않으면 그 폴더의 신원 파일부터 지워 다시 넘겨지지 않게 하고, 바꾸기는 성공으로 두고 로그에만 남긴다 — 기본 칸은 이미 바뀌었고, 같은 토큰을 다시 넘기면 로그인이 폐기될 수 있다 — 틀리면 그 계정의 다음 바꾸기가 "Could not clear an old sign-in"으로 막힌다
- Ruling: 한 번에 하나는 둘째 요청을 바로 거절하는 것으로 한다(줄 세우지 않음). 빌려줄 로그인 지우기도 바꾸기나 복구 중이면 거절한다 — F8과 같은 뜻이고, 지우기와 돌려주기가 같은 폴더에서 겹치지 않는다 — 틀리면 바꾸는 동안 지운 계정의 빌려줄 로그인이 바꾸기가 끝난 뒤에 지워진다
- Ruling: Claude Code 신원 파일이 JSON으로 읽히지 않으면 0.3초 간격으로 두 번 더 읽는다 — 열린 세션이 자주 쓰는 파일이라 쓰는 도중을 읽을 수 있다 — 틀리면 드물게 R9가 거짓 실패한다
- Ruling: 버튼과 "In Claude Code" 표시를 스케치 A의 새로고침 아이콘 옆이 아니라 계정 이름 아래, 제공자 이름 옆에 둔다. 창 맨 위라는 점과 결과 줄이 그 아래라는 점은 같다 — 계정 이름의 기본값이 긴 이메일이라 아이콘 옆이면 열두 글자쯤에서 잘린다 — 틀리면 스케치 위치로 옮기고 이름이 잘리는 것을 받아들인다
- Ruling: 개발용으로 띄운 앱(`AGENTBAR_DATA_DIR`나 `AGENTBAR_DEFAULTS_SUITE`가 있을 때)에서는 이 기능을 끈다 — 개발용 앱이 실제 기본 로그인을 바꾸거나 설치된 앱의 바꾸기와 겹치면 안 된다 — 틀리면 개발용 앱으로는 이 기능을 화면에서 볼 수 없다(시험이 그리는 그림으로 본다)
- Ruling: Claude Code가 없다고 확인된 때만 버튼을 숨기고, 앱을 켜는 중이거나 판을 아직 못 읽었으면 "Checking Claude Code…"로 막아 둔다. 설치 여부는 엔진이 따로 본다 — 판을 못 읽은 것(막힘)과 없는 것(숨김)을 가른다 — 틀리면 Claude Code가 없는 Mac에서 앱을 켠 직후 막힌 버튼이 잠깐 보인다
- Ruling: 앱을 켜는 동안(복구와 계정 UUID 채우기가 끝나기 전)에는 모든 Claude 계정의 Delete와 Reconnect를 막는다 — 복구가 어느 계정 폴더를 쓰는지는 엔진만 안다 — 틀리면 앱을 켠 직후 잠깐 그 메뉴가 회색이다
- Ruling: F8의 앞 계정은 AgentBar가 마지막으로 읽은 Claude Code 계정이다 — 터미널에서 바꾸자마자 누르면 실제 앞 계정이 잠기지 않지만, 엔진이 바꾸는 동안 빌려줄 로그인 지우기를 거절하고 Reconnect는 사용량 로그인만 바꾸므로 꼬이지 않는다 — 틀리면 그 짧은 틈에 실제 앞 계정의 Delete가 막히지 않는다
- Ruling: 바꾸는 동안 다른 계정 창에는 "Switching Claude Code to <이름>…"을 보이고 Cancel은 브라우저를 기다리는 대상 창에만 둔다 — F8의 진행 중 표시이고 취소는 그 창의 일이다 — 틀리면 다른 창에서도 취소하려면 한 줄을 더한다
- Ruling: 브라우저 대기 줄에 그 계정의 등록된 이메일을 넣는다("Sign in as <email> in the browser once…") — 브라우저가 다른 계정에 로그인돼 있으면 F12로 한 번 실패하기 쉽다 — 틀리면 이메일이 나중에 바뀐 계정은 옛 이메일이 보인다
- Ruling: 모르는 계정 확인 줄은 그 창이 닫히면 버린다 — 지워질 로그인에 대한 동의가 오래 남지 않게 하고, 쿠폰 확인 줄과 같게 한다 — 틀리면 다른 데를 눌렀다 돌아오면 다시 눌러야 한다
- Ruling: 새 바꾸기를 시작하면 모든 계정 창의 앞 결과 줄을 지운다 — 앞 결과는 이제 바뀔 로그인에 대한 말이라 남기면 틀린 말이 된다 — 틀리면 결과를 읽던 창에서 새 바꾸기를 누르는 순간 앞 결과가 사라진다
- Ruling: 이미 그 계정이거나 취소했으면 결과 줄을 만들지 않는다. 브라우저를 열 수 없어 끝난 경우는 그 이유를 실패로 보인다 — 할 말이 없는 경우다 — 틀리면 잃는 것은 없다
- Ruling: 앱을 켤 때 끊긴 바꾸기를 정리했으면 그 결과를 대상 계정 창에 보인다. 마저 끝냈으면 초록, 되돌렸으면 주황 "AgentBar quit while switching. Nothing was changed."이다 — 누른 일이 어떻게 됐는지 알린다 — 틀리면 되돌린 경우의 줄 하나를 뺀다
- Ruling: F16의 닫힘은 그 창이 열려 있는 동안 실제로 보인 계정에만 센다. 결과가 닫힌 창에서 생겼으면(브라우저를 거친 경우) 그 뒤 처음 열었다 닫는 것이 첫 번째 닫힘이다. 메뉴 막대 그룹이 새로 만들어지면 첫 탭부터 다시 센다 — 보지 못한 결과, 특히 앱을 켤 때의 복구 결과가 지워지면 안 된다 — 틀리면 결과가 한 번 더 남는다
- Ruling: F10의 이유는 이미 머리 아래에 있는 상태 줄로 삼고 막힌 버튼의 도움말에도 건다. F9와 "계정을 구별할 수 없음"은 상태 줄이 말해 주지 않으니 주황 줄로 보인다 — 같은 문장을 두 번 쓰지 않는다 — 틀리면 상태 줄 문구가 바뀔 때 이유가 안 보일 수 있다
- Ruling: Claude Code 판과 설치는 사용량 새로 고침(주기, 새로고침 버튼, 로그인 뒤)마다 읽고, 팝오버를 열 때는 로그인만 다시 읽는다. Claude 계정이 하나도 없으면 아무것도 읽지 않는다 — 가장 단순한 주기이고, 보일 곳이 없으면 `claude`를 띄울 이유가 없다 — 틀리면 새로고침 버튼이 `claude --version`을 한 번 더 띄울 뿐이다
- Ruling: 저장소를 못 읽었으면 앱을 켤 때 복구를 하지 않는다 — 계정 목록이 비면 엔진이 대상을 못 찾고 기록을 지운다 — 틀리면 잃는 것은 없다
- Ruling: 사용자가 누른 Delete가 바꾸기 잠금으로 거절되면 이유를 알리고, 앱을 켤 때 하는 남은 삭제 정리는 조용히 건너뛴다. 바꾸는 중에는 잠긴 계정의 Reconnect 확정을 거절하고(로그인은 검토 상태로 남는다) Add Account는 막지 않는다 — 확인한 삭제가 말없이 사라지면 안 되고, 새 계정은 잠긴 계정의 신원을 바꾸지 않는다 — 틀리면 로그인 확정 뒤 정리가 잠긴 계정을 만날 때 삭제 문구가 뜬다
